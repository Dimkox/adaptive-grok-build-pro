No cross-provider fallback, silent model remapping or retry occurs. Returned model identity must match the chosen profile exactly. Image/audio use real base64 content blocks; image transfer accepts PNG/JPEG subject to intake's stricter existing limit and the 20 MiB provider bound. Audio base64 must be **strictly below 10,000,000 bytes** and use WAV or MP3. OGG/WebP and other unsupported formats stop with a private `needs_human` reason. Intake format support alone does not imply provider capability.

PDF text extraction uses the narrowly added factory dependency `pypdf==6.18.1`. A separate isolated child sets CPU, address-space, file-size, descriptor and process limits before importing the parser. It receives a scrubbed environment, bounded stdin/stdout/stderr and a 20-second parent deadline, and is killed/reaped on failure. It retains the current virtual environment interpreter so the pinned parser is available. Encrypted, malformed, over-100-page, empty/scanned or over-text-budget PDF becomes `needs_human`; there is no OCR claim or hidden model fallback. Extracted text is normalized and bounded to 65,536 UTF-8 bytes.

HTTP requests are bounded to 30 MiB, responses to 1 MiB and decoded drafts to 256 KiB. Profiles default to 4,096 output tokens and a 60-second HTTP budget, with closed upper bounds of 8,192 and 300 seconds. HTTPX runs beneath an absolute asynchronous timeout and monotonic acceptance checks, disables environmental proxies/redirects and performs no automatic retries. Synchronous callers on an active event-loop thread fail before transport; the API already offloads synchronous landing submission to a worker thread.

Qwen Omni requests `stream=true`, `modalities=["text"]`, and `stream_options.include_usage=true`. The bounded incremental SSE decoder accepts text deltas, terminal `stop`, the final empty-choices factual usage chunk and `[DONE]`, with one stable response ID and the exact model. It rejects missing usage, partial/oversized streams, tool/audio/refusal output and invalid ordering; reasoning is not retained. Nonstreaming profiles likewise require one terminal assistant text choice and factual bounded token usage. HTTP success evidence is additive disposition `normalized`, adapter `https-chat-completions` version `1.1.0`; previous `fixture_ready` records remain accepted. ## Ownership and recovery

Landing SQLite retains WAL/FULL behavior and takes a nonblocking lifetime `landing.writer.lock` before opening or recovering state. The publication database independently takes `.intent-writer.lock`. Do not remove either lock to bypass a running writer. Do not share quarantine, scratch or artifact roots across different stores/operators. Server-owned resources close on composition failure, startup failure, ASGI shutdown and process exit; injected services remain caller-owned.

At most 100 interrupted landing rows are recovered per startup: accepted inputs become `input_unavailable_after_restart`; normalizing becomes `provider_outcome_ambiguous`; interrupted local render/evaluation becomes `local_run_interrupted`, all `needs_human`. Startup does not replay a model request. Larger interrupted populations require a separately controlled bounded recovery procedure. Artifact tampering fails closed. Ambiguous publication remains observation-only via its independent coordinator; no startup or restore automatically republishes.

`adaptive-landing-state backup --config <config> --snapshot <new-private-path>` requires the service and publication writer to be stopped: it acquires their same lifetime locks before snapshotting. It uses SQLite's backup API to include committed WAL-visible pages, creates standalone database files, copies the exact private artifact files and writes a manifest last. It refuses links, unexpected artifact names, overlapping roots and existing destinations. Limits are 4,096 files, 512 MiB per file, 4 GiB total IO accounting and 180 seconds. A failure leaves a partial directory for preservation; absence of the final manifest means no complete snapshot. It does not copy credentials, raw quarantine input, scratch, the source clone or the external deployment root.

The printed manifest SHA-256 must be retained separately with the snapshot record. It is integrity evidence, not production authority. Run backup/restore as the dedicated `adaptive-l5` data owner under their own exact operational authorization. Before restoration, stop the service/publication writer, set `live_enabled=false`, preserve the existing state/publication/artifact roots by moving them to explicitly named inactive locations, and leave the original configured paths absent. `adaptive-landing-state restore --config <config> --snapshot <path> --manifest-sha256 <saved-digest>` checks the closed manifest and file digests, refuses any existing destination and recreates only the exact original paths. This preserves absolute retained-artifact references without rewriting sealed records. Restore failure leaves partial new roots inactive; preserve them and do not start the service. The original deployment target is not reverted by this state restore; reconcile it by observation before any later publication action.

For a binary rollback, keep the service stopped, retain the current release/config/state snapshot and select the previous generated unit only when its landing schema and retained source epochs are compatible. Do not downgrade unknown schemas. A default-off restart of the current release with the same durable roots is the bounded containment path when compatibility is unknown. Activation/rollback of the site itself uses the exact persisted predecessor through the publication CLI, with its separate grant.
