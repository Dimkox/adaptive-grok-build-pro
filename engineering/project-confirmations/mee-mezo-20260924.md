## Product outcome

Build one end-to-end scenario: **verifiable report → API → test MUSD payment → result**.

A user selects BUY/SELL and BTC quantity. The service captures public Hyperliquid BTC-perpetual order-book evidence, validates data quality and instrument identity, calculates the hypothetical sweep with exact arithmetic and stores an immutable report before offering payment. The preview identifies the snapshot time, limitations and price. After confirmed test MUSD payment, the user receives JSON, a readable report and the input bundle with an offline verifier. Subsequent retrieval of the same paid artifact does not charge again.

The payment purchases an evidence report, not BTC, a trade, an investment recommendation or a return. The existing Python Stage A remains public/read-only. Do not change its strategy verdict or turn `INSUFFICIENT_EVIDENCE` into trading authority to make a demo pass.

Excluded: mainnet, autotrading, exchange credentials, custody, live Lighter capture, cross-venue arbitrage, unrelated platform integrations, fabricated payment success and hidden fixture-to-live substitution. Receiving test MUSD requires its own explicit test-wallet operation; registration does not send funds.
