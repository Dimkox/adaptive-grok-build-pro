# Предлагаемые GitHub Milestones

Сейчас в GitHub нет milestones и issues. План ранее вёлся в файлах репозитория и PR. Ниже — проект семи milestones: один закрытый ретроспективный и шесть открытых. Создание и изменение GitHub объектов ещё не выполнялось.

| Этап | Начальное состояние | Что учитывает |
| --- | --- | --- |
| M0–M9 — Поставленная базовая реализация | Закрыт: поставленный код | Ретроспективный учёт поставленного исходного кода M0–M9. Поставка основной реализации подтверждена PR #22 и историей main; эта отметка не означает завершённую эксплуатационную квалификацию, действующий M8 или автономный production deploy. |
| M7.1 — Постоянное хранение доказательств и preflight | Открыт | Ближайший срез: сохранять канонические bundle/outcome и отдельно полученные наблюдения о приёмке и актуальности, связывая их с repository/task/run/result SHA. Добавить отдельный результат preflight; существующие блокировки V1, потолок L2 и отсутствие эксплуатационных полномочий сохранить. |
| M7.2 — Рабочий shadow-цикл и измерения | Открыт | Демонстрировать ограниченный цикл задача → изолированное выполнение → независимая проверка → PR → человеческое решение, с наблюдаемыми расходами и вмешательствами. |
| M8.1 — Квалификация точных профилей до L2 | Открыт | Собирать и проверять фактические когорты для точной комбинации класса задачи, агента, модели, промпта, валидатора, политики, runner и holdout. Рекомендация отделена от активации. |
| M9.1 — Повторяемая доставка и восстановление | Открыт | Проверить preview/staging/canary и восстановление из подписанного артефакта точного merged SHA в явно разрешённой среде. |
| L3–L4 — Ограниченная автоматизация и отзыв полномочий | Открыт | Предложение будущего этапа, заблокированное до отдельного утверждения границ полномочий. Определить допустимые классы автоматического merge, аудит, мониторинг и автоматический отзыв. |
| L5 — Критерии и эксплуатационное доказательство автономности | Открыт | Сначала утвердить измеримое определение L5: классы задач, среды, допустимые эффекты и границы человеческого вмешательства. Затем показать повторяемую работу полного цикла по этому протоколу. |

Точные заголовки, описания и состояния подготовлены в [github-milestones.json](github-milestones.json). Предложенная операция — только создание этих семи milestones в Dimkox/adaptive-grok-build-pro; создание issues, перенос PR, merge, release и deploy сюда не входят. При повторном запуске сначала сверить все существующие milestones, чтобы не создать дубликаты.

M7.1 имеет отдельный [проект решения](architecture.md) и [критерии](requirements.md). Предлагаемые шесть задач для него приведены в [анализе планирования](evidence/analysis-docs_researcher.md); это пока текст, не созданные issues. Даты и проценты прогресса не выдумываются. Закрытие ретроспективного этапа означает поставку кода, а не прохождение оставшихся эксплуатационных критериев M7–M9.
