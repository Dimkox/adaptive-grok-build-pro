# Acceptance

- AC-001: Bounded safe inspection distinguishes legitimate draft omissions from invalid or incomplete active packages, without following links or scanning arbitrary logs.
- AC-002: Status retains existing JSON fields and adds package and Git diagnostics without creating runtime directories, bytecode, index refreshes or repository changes.
- AC-003: Dirty product work at zero task commits is visible with exact named checkpoint or route baseline; missing or failed Git evidence remains unknown, including unusual filenames.
- AC-004: Explicit current template or mandatory-obligation omissions are visible, historical quoted examples are preserved, and not_run with reason accounts for work without supplying passing evidence.
- AC-005: Start and first implementing transition record durable immutable-start and WIP observations while repeated starts preserve history; no archive migration or automatic publication occurs.
- AC-006: Stop remains warning-only, failed reviews remain recordable, pass-review diagnostics have no circular receipt prerequisites, and existing receipt/external authority semantics remain unchanged.

Detailed boundary cases are in [the architecture analysis](evidence/analysis-architect.md) and [integration analysis](evidence/analysis-integration_architect.md).
