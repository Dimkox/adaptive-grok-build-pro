# Integration analysis: scratch and evidence fingerprints (#168)

Status: ready for the selected single writer. Read-only analysis against the frozen `1f7aedb8` wave base; no full gate was run.

## Call chain and invariants

`.grok-stack/adaptive_grok/util.py:145-179` currently unions committed/base diffs, staged diffs, unstaged diffs, and `git ls-files --others --exclude-standard`; every path then passes the same `_fingerprint_noise` filter. `tree_fingerprint()` at 183-200 hashes HEAD plus path and current file bytes. Its consumers include verification's start/end source-stability comparison and changed-file scan, route and state snapshots, review/approval receipts, and publication binding (`scripts/grok_landing_publish.py`). A broad `.qwen/` exclusion or generic ignore configuration would make tracked configuration/source changes invisible to these callers. It would also hide a staged scratch file that is now part of the proposed tree.

Filter only the *untracked* Git result, after provenance is known, for narrowly named generated directories such as top-level `.qwen/tmp/` (and only other empirically established agent scratch paths). Leave the existing noise rules in place. Keep every tracked, staged, and committed file in `.qwen/`, `.codex/`, `.agents/`, or equivalent directories bound, including files under `tmp/` if Git tracks them. Because `git ls-files --others` normally excludes tracked paths, the safest shape is a separate untracked predicate applied only to that command's output; if the implementation separately queries tracked status, a Git failure must keep the candidate in the hash. No fallback may silently classify an unknown file as ignorable. The no-HEAD filesystem walk also lacks tracked/untracked provenance, so it should conservatively include scratch unless an equally reliable tracked-set check succeeds.

Changing `changed_files()` changes more than receipt freshness: `verification.py:555-585` also feeds its result into secret scanning, contract checks, and the changed-file report. Only narrow generated scratch should leave those scans. Preserve the existing source-stability failure when any genuine product/control file changes during verification. The present silent treatment of other Git command failures is a pre-existing concern; do not broaden a narrow scratch repair into a new skip path.

## Focused acceptance

In a disposable Git fixture, establish a baseline fingerprint, create and remove an untracked `.qwen/tmp/probe`, and assert the fingerprint and verification changed-file inventory stay fixed. Change a tracked `.qwen/tmp/*` file and tracked `.qwen/`, `.codex/`, and `.agents/` configuration; each must alter the fingerprint. Stage a new scratch file and assert inclusion. Add an untracked `.qwen/config` or `.agents/skills/*` file and assert inclusion. Simulate failure of any tracked-set query used by the filter and assert conservative inclusion. Check that receipt validation remains stale for a real tracked change and fresh for untracked scratch churn. Existing issue evidence already gives a measured A/B `.qwen/tmp` flip; these tests should reproduce it locally without running the full gate.
