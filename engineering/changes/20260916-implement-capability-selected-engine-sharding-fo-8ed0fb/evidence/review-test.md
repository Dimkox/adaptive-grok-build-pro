Nothing pins "root with no opt-in config still yields a passing `python-unittest` check" for the actual tree the gate runs on, and (per §5) that very branch is PATH-dependent. Add one test that calls `_python(ROOT, mode='pr')` (or asserts the root stays un-opted-in and the legacy branch green).
- **F2 — the strict-pin test's name claims more than it tests; pin-equality is untested (arm H survived).** `test_importable_but_mismatched_parallel_dependency_still_fails` patches `metadata.version` with `PackageNotFoundError` — i.e. a **missing** distribution, not a mismatched version. `python_test_runner.py:184` (`{name} requires tested version {PINS[name]}; found …`) is uncovered (coverage lists 184) and disabling it entirely survives. Fix: patch `metadata.version` to return e.g. `'9.0.0'` for `pytest` and assert fail + that message.
- **F3 — the xdist-only skip is invisible in machine counts.** `continue` inside `with self.subTest(...)` yields an empty passing subtest (0 skips reported). Verified alternative: `self.skipTest('…')` inside the same subTest block reports `test_loop … (scenario='b') ... skipped '…'` and still `OK (skipped=1)`. Use it so a reader of `Ran 19 … OK` can see the deferred scenario (this is the retake's own blind spot, and a counts-only gate cannot detect it).

**Suggestion**
- **F4 — engine disclosure is pinned in only one direction.** Arms **N** (an explicitly serial `workers=0` run mislabelled `unittest-degraded`) and **O** (`_python` summary always claiming `pytest-xdist`) both survive: no assertion pins the `workers==0` label (control, unmutated: summary `unittest workers=0`, versions `{"engine": "unittest"}`) nor the summary's backend token — only the degraded *details* label is checked. Cheap fix: assert the exact `json.dumps` value (or `'unittest-degraded' not in …` on the `workers=0` and `GROK_TEST_WORKERS=0` fixtures) and assert `summary.startswith('unittest ')` in the degrade test.
- **F5 — bounded-config validation is largely untested: arms P (config `workers` upper bound), Q (`GROK_TEST_WORKERS` validation), S (`schema_version`) survive**, and coverage shows the `RunnerError` raises at `python_test_runner.py:36, 52, 54, 59, 63, 66` never executed in-process (49/59 only inside the mkfifo child, which this measurement cannot see). A regression that accepts `{"workers": 10000}` or `GROK_TEST_WORKERS='10e9'` would ship silently. Add parametrised `selected_workers` rejection cases (duplicate key, symlink, >4 KiB, wrong key set, `schema_version: 2`, truncated JSON, `GROK_TEST_WORKERS` = `''`/`-1`/`65`/`077`).
- **F6 — xdist distribution semantics are unverifiable on this host (arms I, J survived) — acceptable, but only because the gate image pins the tools.** `trust-ci/runner.Dockerfile` (commit `a730ee9`, "#34") installs `pytest==9.1.1 pytest-xdist==3.8.0 pytest-cov==7.1.0 coverage==7.15.4`, so in the container `parallel_engine_ready(measured=True)` is true and the `missing-worker` scenario *does* run, and `test_parallel_coverage_preserves_parent_and_existing_data` supplies the positive control (undamaged `workers=2` fixture → `coverage pass`) that makes the `missing-worker` `status=='fail'` discriminating. Residual risk: nothing in this repository's evidence proves that container-side arm was ever executed. Ask for one recorded run of this module on the pinned image (or a `--dist=loadfile` distribution assertion) before closing AC-001..AC-004 as fully verified. Related: arm **L** (degraded measured path stops requiring pinned `coverage`) survives because `coverage` is present here; it is only killable on a host without it.
- **F7 — non-Linux descendant checks degrade silently rather than skipping.** `assert_descendant_stopped` reads `/proc/<pid>/status`; on any non-Linux POSIX system the very first `FileNotFoundError` causes an immediate `return` (success), so the kill-group assertion becomes vacuous with no skip marker (`_stop`'s Windows branch at `:101-102` and the non-POSIX `_pytest_command` raise at `:210-211` are likewise untested). Guard with `unittest.skipUnless(sys.platform.startswith('linux'), '/proc required')` or fall back to `os.kill(pid, 0)`. This host is Linux, so no action is required for this PR — it is a portability-of-evidence note.
