# External ownership and bounded repository mitigations

These are the host/tool/provider parts of the assigned 17-issue subset. The issue snapshot is dated; no live provider/version check or external issue comment was made during this research. A repository document or local receipt cannot fix an agent runtime, edit tool, pnpm install, TUI bundle, GitGuardian detector, or network proxy.

| Issue | Missing owner/control outside this repo | What this repo can safely do now |
| --- | --- | --- |
| #97 fabricated in-progress verdict | Agent model/prose generation and completion notification channel. | Reuse open PR #134 to reject absent/invalid report receipts; require observing the actual report before a completed-review statement. This cannot prove every sentence true. |
| #96 completed-agent resume `DOMException` | Agent lifecycle/resume implementation and transcript preservation in host runtime. | Order reviewer work as file first, summary second; use #134's report/digest gate; treat missing file as incomplete and relaunch a bounded review rather than trusting a chat verdict. |
| #76 `data_inspection_failed` | Chat backend moderation/error response, request-ID propagation, partial transcript persistence. | Narrow evidence reads, checkpoint reports early, report `failed` distinctly, and retry once with smaller scope. Do not infer the trigger from a coincidentally long/non-ASCII transcript. |
| #74 edit reports error after write | Edit tool's freshness-token/write-result implementation. | Reread and compare intended target content after that exact error before any retry. `.grok/hooks/post_tool_use.py` only writes runtime fingerprint/receipt state, not the target, so a hook-caused target mtime change is unproven. |
| #73 GitGuardian digest false positive | GitGuardian detector/settings and disposition service. | Preserve frozen evidence, choose neutral keys for new evidence after consumer-schema review, and cite the prior disposition when triaging a repeat. Do not turn off broad secret detection. |
| #58 wrong-worktree branch push | Operator/host shell invocation remains capable of bypassing a fail-open local hook; remote controls PR ref. | Ship a checked single-ref helper and exact grant/ref binding design (see `design-push-58.md`), with normal non-force remote push. This cannot override a raw out-of-band shell or supply merge authority. |
| #47 Ink/React #185 | Qwen Code CLI/Ink bundled implementation and release channel. | Document dated symptom/corrections and preserve diagnostic evidence; the repository contains no Qwen Code CLI bundle to patch. A later upstream version must be checked by its owner. |
| #45 agent dies silently | Host task terminal-status reason, heartbeat and write-status API. | Require artifact/status inspection before treating a review/write task as complete; no evidence identifies the death cause. |
| #44 worktree isolation from non-repo root | Agent tool repository-target selection. | Supply absolute target repo/worktree in task briefs and document a manual `git -C` worktree fallback; no tool isolation code is present here. |
| #43 non-TTY pnpm purge | A separate Node workspace's pnpm/store/config and package-manager behavior. | Record the hard-stop diagnostic pattern; current checkout has no pnpm workspace, so there is no runnable local correction. |
| #42 proxy timeout masquerades as outage | Host proxy routing and target network path. | Report proxied and direct observations separately in any future health-probe utility. Product live provider client already sets `trust_env=False`; no current adapter repair is indicated. |
| #41 lost agent completion notification | Host result-delivery queue and completed/unreported status semantics. | Check expected report file and explicit task status before retrying; local `subagent_stop` records only a stop event and does not deliver a result. |

Historical local shell/config classes #35, #36, #37, #38, and #40 need a concrete current-tree reproduction before product work: this checkout has no `verify:deploy` or `pnpm` gate, no pre-push installer, no broad `*.log` ignore, and top-level verification already runs synchronously. Their examples remain useful regression patterns when introducing a corresponding component.
