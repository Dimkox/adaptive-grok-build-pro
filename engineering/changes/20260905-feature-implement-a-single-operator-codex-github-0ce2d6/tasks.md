# Five sequential implementation tasks

Each task has one unambiguous output consumed by the next. Exactly one `integration_implementer` owns every source edit.

## Task 1 — freeze the boundary and contracts

- Add the separate `pilot/` package, exact landing profile, five JSON schemas and architecture model/diagrams.
- Add failing contract/profile/architecture tests first.
- Output handoff: canonical `profile_digest` plus schema-validated `IssueSnapshotV1` fixture.

## Task 2 — produce one sealed candidate

- Add private exact-base Git workspace, live/fake issue source, pinned one-start Codex executor and private durable store.
- Prove sandbox prerequisite/denial, remote removal, allowlisted diff, modes, parent/tree and terminal no-retry recovery.
- Output handoff: stored `CandidateChangeV1` linked to the Task 1 snapshot/profile.

## Task 3 — validate the frozen candidate

- Add the one-command credential-free bubblewrap runner and deterministic status/version/CSP semantic gate.
- Reject mutation, timeout, overflow, nonzero, identity mismatch and every semantic non-pass.
- Output handoff: stored `CandidateValidationV1(decision=pass)` bound to the exact candidate SHA/tree.

## Task 4 — prepare and publish one draft proposal

- Add literal exact-resource grant adapter, non-force branch publisher, draft PR publisher and observation-only reconciliation.
- Persist prepared intent before effects; prove no merge/close/deploy/duplicate or automatic write retry path.
- Output handoff: `PullRequestProposalV1` with exact branch/PR identities or a typed terminal outcome.

## Task 5 — integrate, document and prove readiness

- Add disabled-by-default CLI, fake end-to-end test, operator runbook, README/PROJECT_STATE/VERSION `2.0.15` synchronization and release/rollback notes.
- Run focused changed tests while implementing. Freeze one source HEAD, then run exactly one detached PR verifier and one parallel code/test/security review wave.
- Output handoff: clean local PR candidate with fingerprint-bound receipts; after merge, one separately granted real issue/Codex/branch/draft-PR attempt.

No task adds a second Codex attempt or expands the target. A failed core check returns only to the owning task; already-passing unaffected checks are not rerun.
