## Finding: two independent scope gaps feed an exit-code-only verdict

1. `verification.py:815–837` defines `QUALITY_PY_PATHS`: stack module, `scripts`, `tests`, hooks/root hook wrappers and `factory/src/adaptive_factory`. `_existing_quality_paths` checks only path existence. Consumer `engineering/product.py`, `src/product.py` and arbitrary product directories are absent before any analyzer configuration is consulted. An installed stack supplies several listed paths, so the check can inspect stack code while overlooking all consumer Python.
2. `_ruff` (`verification.py:840–846`) runs `ruff check <existing fixed paths>`. `_bandit` (`849–858`) drops only the top-level `tests` target, then runs `bandit [-c bandit.yaml] -q -r <paths>`. Neither obtains or intersects the analyzer's actual selected files with changed product paths.
3. `_command_check` (`353–362`) maps exit 0 directly to `pass`, with summary `exit=0`; it retains only the last 12,000 characters per stream. It records no scope count, file identity, selection completeness, parsed/skipped-file information or distinction between stack and consumer checks. Scope cannot safely be reconstructed later from the retained tail.
4. `ruff.toml:4–12` excludes `engineering`, `packages`, `examples` and `dist`; `bandit.yaml:1–7` excludes the same families plus `tests`. `.coveragerc:3–10` measures only `.grok-stack/adaptive_grok` and `scripts`, omitting `engineering`. Removing one exclusion would not repair the fixed-target omission or unsupported-language gap.
5. Production `verify` gathers checks then uses only `result.status == 'fail'` to determine the verdict (`verification.py:1094–1148`). Thus stack passes plus product skips/absence produce an overall pass. The issue's cited line 1060 now belongs to the separate, pure **sample-report** summarizer (`1026–1067`), not the production verifier; changing only that function would not fix this defect.

These are source-derived causal facts, not a newly measured reproduction. The archived issue's consumer counts and A/B tool outputs remain reporter-provided evidence.

## Inventory seam: preserve provenance, expose uncertainty

`verification._changed_file_inventory:550–591` unions worktree changes with every selected route/PR comparison range in PR/release. Keep that union: a route created after an earlier commit can otherwise miss product files visible only from the real PR base. Existing tests cover this at `tests/test_verification_doctor.py:319–398` and subsequent range-selection cases through line 607.

`util.changed_files:160–197` retains staged/unstaged/base-relative changes and untracked files. Git requests use `-z`, `--no-renames`, `os.fsdecode`, and preserve tracked deletion/rename provenance even inside normally ignored scratch. Do not substitute newline splitting, decode-with-replacement, blanket excluded-prefix filtering or only `git diff HEAD`.

It is **not** a bounded complete consumer-inventory API today: `_git_paths:145–157` captures unbounded output and returns `None` on error/malformed termination; individual failed diff queries only lower a local `tracking_known` flag, and an untracked query failure is consumed as empty. No explicit incomplete diagnostic reaches `_changed_file_inventory`. Without HEAD, `root.rglob('*')` walks the tree with no aggregate entry/depth/byte budget (`184–197`). These cases must not be converted into evidence of zero product changes.

Relevant reusable precedent, not a drop-in coverage inventory: `package_status.py:386–456` uses capped binary Git queries, explicit unknown/error results, bounded path counts and lossless non-UTF-8 representation; limits are at `18–26`. Its `_product_path` excludes all `engineering/changes/` for checkpoint diagnostics, so it is not an installed-consumer ownership policy. `architecture_diff.py:74,159,174` provides the capped process and constrained Git helpers it uses. Recheck lifecycle/doctor process APIs on the actual delivered parent before reuse.

The new design should retain deleted paths in change diagnostics while distinguishing them from current files analyzers can inspect. A rename needs both original and destination provenance; a new destination outside a traditional source root is still product. Malformed/overflowed analyzer output, unsafe paths, unavailable inventory, symlinks and truncation need an explicit incomplete reason, never an invented zero. Intersect actual selected path identities with relevant product paths; a positive count consisting entirely of stack files is insufficient.
