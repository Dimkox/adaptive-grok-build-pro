# Documentation analysis — issue #124

## Current normative text and reviewer entrypoints

- **The only explicit repository-wide mutation-testing requirement found** is `DARK_FACTORY_ROADMAP.md:1085`: every milestone's testing requirements include “mutation tests for critical policy gates.” This mandates mutation tests for critical policy-gate behavior, but does not assign execution to code/test reviewers or specify isolation, scratch-copy handling, or report evidence.
- **The reviewer briefs are `.grok/agents/code_reviewer.md` and `.grok/agents/test_reviewer.md`.** Their YAML descriptions/body currently ask for independent final-diff review or test-adequacy review, reading the change package, and avoiding secrets or external operations. Neither asks for mutation testing, a scratch copy, commands/output, or a claim-by-claim execution record.
- **The corresponding agent policies are `.grok/agents/code_reviewer.toml` and `.grok/agents/test_reviewer.toml`.** Both explicitly say `sandbox_mode = "read-only"` and require a concrete report with findings, residual risk, and a pass/fail recommendation. This supports keeping the reviewed tree read-only; it does not prevent work in an explicitly private scratch copy. These TOML instructions also currently omit mutation testing and the requested evidence fields.
- **Repository-level delivery policy** is `AGENTS.md` under “Local verification and completion” (around line 150): dispatch route-selected reviewers, store reports under the change package or `engineering/reviews/`, and record report paths. It does not define mutation checks or report contents. Add the scratch/isolation and evidence requirement here if it is intended to be a factory-wide rule.
- **Workflow instructions are duplicated:** `.agents/skills/adaptive-delivery/SKILL.md` and `.grok/skills/adaptive-delivery/SKILL.md` both specify independent final-tree review and report storage, without mutation tests. They are not byte-identical today (`.grok` has an additional Tool-denial circuit breaker section), so update both intentionally and do not blindly copy one over the other. `.agents/skills/verification-evidence/SKILL.md` and `.grok/skills/verification-evidence/SKILL.md` also request reports and receipts but no mutation evidence; amend both if their generic review procedure is meant to carry this requirement.
- **There is no dedicated code-review or test-review report template.** `.grok-stack/templates/change/evidence/README.md` only says to store human-readable reports there and that machine receipts live under runtime; it is the single report-folder guidance/template-adjacent file. Updating it to state required report fields is appropriate. Existing `engineering/changes/**/evidence/*review*.md` are historical report examples/evidence, not reusable canonical templates; they contain numerous mutation narratives but should not be retroactively edited.

1. Define in `AGENTS.md` and the two adaptive-delivery skill copies that code/test reviewers perform bounded, change-relevant mutation testing in a reviewer-owned private scratch copy outside the reviewed worktree; the reviewed tree remains read-only and must not be restored/modified by the reviewer. Scope mutants to claims/changed behavior and critical relevant branches; record survivors as findings or an explicit limitation rather than implying success.
2. Extend `.grok/agents/code_reviewer.md`, `.grok/agents/test_reviewer.md`, and both TOML policies with the same operational rule. Do not make mutation score a blanket pass threshold unless the issue/maintainer policy explicitly chooses one.
3. Update `.grok-stack/templates/change/evidence/README.md` with a concise review-report checklist/template reference. The canonical `code-review.md` / `test-review.md` files are currently conventions only; if adding standalone templates, keep them under this template directory and ensure they are included by normal packaging.
4. Add regression tests in `tests/test_structure.py` (or a focused reviewer-policy test) that assert both reviewer briefs and their paired TOMLs contain the scratch isolation, no reviewed-tree mutation, and evidence/report fields; assert both skill copies preserve the rule; and assert the evidence README exposes the report contract. `tests/test_manifest_package.py` validates source/package consistency broadly, so the normal package verifier should pick up modified managed files; no installer behavior change is implied by #124. The scope is prompt/policy/report contract plus regression protection, not a mutation-test runner or automated sandbox service.
