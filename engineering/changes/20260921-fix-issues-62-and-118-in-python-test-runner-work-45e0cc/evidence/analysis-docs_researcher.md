## Primary-source facts

- **v2:** `cpu.max` contains quota and period, with microseconds as the interface's default time unit; `max` means no local quota. The file exists on non-root cgroups. The v2 membership record is `0::PATH`; resource restrictions remain hierarchical. Thus an unlimited leaf does not remove an ancestor's cap. [Kernel CPU interface](https://docs.kernel.org/admin-guide/cgroup-v2.html#cpu), [conventions](https://docs.kernel.org/admin-guide/cgroup-v2.html#conventions), [membership](https://docs.kernel.org/admin-guide/cgroup-v2.html#processes), [delegation](https://docs.kernel.org/admin-guide/cgroup-v2.html#model-of-delegation).
- **v1:** `cpu.cfs_quota_us` supplies runtime per `cpu.cfs_period_us`, both in microseconds; `-1` denotes unconstrained bandwidth. A group can be throttled by exhausting its own quota or its parent's. Quota measures aggregate CPU time, not a reserved CPU count. [Kernel bandwidth management](https://docs.kernel.org/scheduler/sched-bwc.html#management), [hierarchical constraints](https://docs.kernel.org/scheduler/sched-bwc.html#hierarchical-considerations).
- **Membership:** v1 records identify the controller list and process's hierarchy path; select the `cpu` controller token, including a combined `cpu,cpuacct` hierarchy, rather than guessing from a directory name. Forked children inherit membership. [Linux cgroups manual, NOTES and /proc files](https://man7.org/linux/man-pages/man7/cgroups.7.html#NOTES).
- **Mount identity:** mountinfo supplies the filesystem's mounted root, the visible mountpoint, filesystem type, and superblock options. Optional fields precede a hyphen separator; positional assumptions after field six are unsafe. [Linux mountinfo manual, DESCRIPTION](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html#DESCRIPTION).
- **Namespace boundary:** membership and mountinfo are virtualized relative to cgroup-namespace roots. Legitimate views may contain `/../`; the documented inherited-mount example exposes mount root `/..` while self-membership is `/`. Such metadata does not justify replacing the process's membership with an arbitrary visible root. [Linux cgroup namespaces manual, DESCRIPTION](https://man7.org/linux/man-pages/man7/cgroup_namespaces.7.html#DESCRIPTION).

## Bounded implementation recommendations

These are conservative product-policy recommendations inferred from the facts above, not kernel guarantees about optimal worker counts.

1. Confine quota discovery to Linux `auto`. Keep explicit worker requests, 28-worker auto ceiling, no-opt-in behavior, child suppression, and capability fallback intact.
2. Parse `/proc/self/cgroup` and `/proc/self/mountinfo` through a small injectable read boundary. Bind v2 membership to `cgroup2`; bind v1 CPU membership to a `cgroup` mount exposing the exact `cpu` controller. Hybrid machines must not confuse an unrelated v2 membership with the v1 CPU hierarchy.
3. For unambiguous paths, remove the mount-root component prefix from membership and append the remaining components beneath the visible mountpoint. Include component-boundary checks (`/team` must not match `/teammate`). Handle or explicitly reject mount path escapes; do not interpret escaped whitespace as extra fields.
4. Inspect the matched leaf and each accessible ancestor through the matched mountpoint, including that boundary. Use every valid finite quota found; an unlimited leaf still needs the ancestor walk. Do not read ordinary filesystem parents above that mountpoint or unrelated sibling cgroups.
5. Reject ambiguous namespace mappings, traversal components, or unreadable/malformed relevant metadata as unknown. Do not normalize `/../` away, strip arbitrary host prefixes, or fall back to `/sys/fs/cgroup/cpu.max` merely because that file exists. A root-only read is justified only when membership mapping establishes that root as relevant.
6. Parse exact quota/period shapes, positive decimal numeric values, v2 `max`, and the v1 read sentinel `-1`; zero period is invalid. Recommended integer policy: `max(1, quota // period)`, then minimum across affinity, finite visible quotas, and 28. The floor is a deliberate conservative choice; kernel documentation specifies bandwidth, not floor/ceiling worker policy.
7. Distinguish **known unlimited**, **known finite**, and **unknown**. Known unlimited can preserve the affinity limit; unknown should use a documented one-worker fallback (or equivalent sequential selection chosen explicitly by the owner). Incomplete ancestor visibility is not proof of globally unlimited CPU. Parent quotas may also be shared, so even a visible finite minimum is an upper bound rather than guaranteed throughput.
8. Keep reads and walks bounded and side-effect free. Use fixture text to cover nested v2, combined-controller v1, mount-root remapping, unlimited leaf with finite parent, fractional quota, unavailable/malformed metadata, mismatched namespace roots, and unrelated mounts. No host-dependent capacity assertions are needed.
