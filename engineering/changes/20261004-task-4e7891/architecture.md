# Bounded state design

Current handoff incorrectly treats an existing owner-accepted factory-built product as an unmet first-pilot prerequisite. Add a separate completed_product_case inside milestones.M8 without altering its five historical delivery axes. The handoff qualification fact points to that case; accepted-product planning is unblocked.

PROJECT_STATE is consumed by the project-state binding tests and human/agent handoff, not factory runtime selectors. No producer, consumer, adapter, API, event, schema, migration or default setting changes. Executable M7 lookup/currentness and M8 empirical activation remain separate prerequisites. Versioning and runtime compatibility are unchanged. Bitrix and deployed governance are unaffected; no new canonical-rule or debt claim is made.

Provenance separates user-confirmed completion/acceptance/factory attribution from API-observed source and release identities and corroborating tooling pin. Main is not the distinct released source. Historical records are retained. Risk: overclaiming activation from one product; mitigate with the explicit remaining inventory and false-boundary regression.
