## Recommended minimal design

Add `.grok-stack/adaptive_grok/python_test_runner.py` as a small invocation/coverage helper, called by `_python`. Suggested boundary: `run_core_tests(root, *, mode, workers) -> CoreTestRun`, returning separate test and coverage process outcomes plus bounded metadata; it must not import `verification.CheckResult` back into itself. Verification wraps these outcomes in its existing report shape. Put process/environment/temporary-artifact handling here, not into the general `util.run` used throughout the repository.

Suggested control `GROK_TEST_WORKERS`: strict integer0..64; zero explicitly selects the existing serial unittest backend, preserving the full selector and PR/release coverage gate. Default parallelism can be min(22, available CPUs), with the effective number visible in evidence; this is a bounded initial policy informed by the host benchmark, not a universal optimum. Malformed/negative/excessive values fail clearly. Tests inside workers must receive `GROK_TEST_WORKERS=0` for nested verifier fixtures, preventing recursive22-worker fan-out.

Use the verifier's exact interpreter for pytest, xdist, pytest-cov and coverage (`sys.executable -m ...`), and validate required modules/versions in that interpreter rather than trusting unrelated PATH executables. An explicitly requested parallel run with missing/incompatible tools is a named failed check with the packaged install command; do not silently retry a failed parallel suite serially. Compatibility fallback for an unconfigured consumer may choose the legacy serial path before executing tests and must report the reason; it never converts missing required coverage into passing coverage. Record installed versions and worker count.

Parallel command shape: exact `tests` selector; `--import-mode=prepend`; fixed rootdir/cwd; `-n N --dist=worksteal --max-worker-restart=0`; explicit `-p xdist.plugin -p pytest_cov.plugin`; disable third-party plugin autoload, inherited PYTEST_ADDOPTS/PYTEST_PLUGINS influence and pytest cache writes. Preserve Core-required PYTHONPATH roots and other legitimate test dependencies. PYTHONDONTWRITEBYTECODE keeps the frozen source clean. Do not pass arbitrary caller pytest options through this runner.

The runner must own the controller's process group, bound its timeout/output, and on timeout terminate/reap that group so xdist children cannot continue writing or running after failure. Limit this to owned processes; no global PID/name sweep. Any collection failure, test failure, worker crash, timeout or cancellation is failure. `--max-worker-restart=0` makes a crashed worker a visible failure rather than an implicit new attempt. A serial rollback does not hide such failure; it is a subsequent explicit run with separate evidence.

## Preserve Core branch coverage74 without stale merging

`.coveragerc` remains authoritative and unchanged: branch=True; sources `.grok-stack/adaptive_grok` and `scripts`; existing omissions; fail_under74. Use its absolute path. `--cov` without a value preserves configured source roots; a valued `--cov=...` would override them. Do not add Factory/Trust files or enable subprocess instrumentation to improve the percentage.

Every invocation owns a unique TemporaryDirectory **outside the repository** containing COVERAGE_FILE and reports. This includes serial/nested verifier runs, which must not overwrite a parent worker's inherited coverage file. Parent/child environment changes are scoped to subprocess arguments, never global environment mutation. Read required report bytes/digests into CheckResult evidence before cleaning the temporary directory; no user `.coverage` erase/append and no repository-wide search for fragments.

Use pytest-cov's worker instrumentation and controller combination for the parallel path. Then run the same interpreter's `coverage report --rcfile=<absolute> --fail-under=74` against only that run's combined file, producing a separate `coverage` result. Reject absent/corrupt/empty combined data, absent branch data, or diagnostics indicating a worker did not return coverage; do not accept another worker's high percentage as proof that all workers contributed. If the selected pytest-cov version exposes missing-worker coverage only as a warning, promote that supported diagnostic to failure or add a narrowly pinned controller completion check and test it. Never manufacture a passing coverage result from pytest exit0 alone.

Keep test and coverage exits independently visible: a test assertion failure may still produce useful coverage evidence, but the overall result remains failed; a test pass with coverage below74 is also failed. If controller/worker failure leaves incomplete data, coverage is failed/unavailable, not a stale report from a previous run. Do not use cov-append or blend baseline and candidate data. Automatic combination behavior varies with coverage versions, so invoke the tested explicit run-local report path and preserve exact version metadata.

Pytest-cov documents combined distributed coverage and the unvalued --cov/absolute rcfile behavior ([xdist](https://pytest-cov.readthedocs.io/en/latest/xdist.html), [configuration](https://pytest-cov.readthedocs.io/en/latest/config.html)). Coverage combines files by source filename ([combine](https://coverage.readthedocs.io/en/latest/commands/cmd_combine.html)); all workers here use one frozen checkout, so no new path remapping is needed. Pytest-cov7 moved subprocess support to explicit coverage subprocess patches ([subprocess guide](https://pytest-cov.readthedocs.io/en/latest/subprocess-support.html)); retain current subprocess scope for parity.

## Bounded opt-in ruling before implementation

Use a new repository-owned root `.grok-test-runner.json` containing exactly `{"schema_version":1,"workers":"auto"}`. It is not one of the verifier's project markers, is not in installer MANAGED_FILES, and `tests/_support.py:14-37` does not copy it into consumer fixtures. The full toolkit archive naturally includes it under existing manifest rules (`manifest.py:57-70`). This enables normal verification for this repository without enabling arbitrary installed consumers merely because managed requirements/config directories exist. Do not couple activation to PROJECT_STATE identity.

Resolve explicit public `GROK_TEST_WORKERS` first, otherwise the closed root config, otherwise preserve the legacy branch. Accept only auto or bounded integer0..64; auto uses the bounded default described above. Present but malformed/oversized/nonregular config is a named failure, not silently absent. Explicit0 is an opted-in serial helper run with fresh coverage data; it does not disable tests/coverage. This config-based decision supersedes any implied blanket default activation in the earlier general recommendation.

Use a separate private nested-run flag as a **cap after opt-in resolution**, never as activation. Child environment removes the inherited public worker override and sets the private cap; an opted-in nested repository runs serially, while an arbitrary copied fixture lacking opt-in keeps its original backend/selector. Every nested legacy coverage invocation must still receive a unique temporary COVERAGE_FILE; retaining legacy semantics does not justify allowing it to overwrite a parent worker's data. A common serial invocation primitive can provide that isolation without changing generic discovery.

Required characterization: current toolkit config activates normal runner; installed target/project_copy lacks activation; explicit override wins; absent both remains legacy; malformed config fails; private guard alone never opts a generic fixture in; opted-in nested execution is serial; parent/legacy-child coverage files never collide. Add no installer enrollment for the root opt-in, new architecture node, or unrelated runner scope.
