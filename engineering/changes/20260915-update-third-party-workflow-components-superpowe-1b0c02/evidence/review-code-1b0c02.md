## New findings (severity sorted)

### N1 — LOW — The F1 regression test pins the copies to each other, not to the emitter

`tests/test_workflow_artifacts.py:787-814` asserts `workflow_artifacts.RECEIPT_KINDS == receipts.RECEIPT_KINDS`, that the two domain kinds are members, and per-kind gap semantics for a hand-written 7-kind route. Nothing in the suite derives the kind set from the emitter, so the exact F1 root cause (a router kind absent from the closed set) can recur silently: adding an eighth `evidence.append('…')` branch at `.grok-stack/adaptive_grok/router.py:403-417` keeps all 87 focused tests green while every such route again fails `validate_evidence` with the opaque message. Suggested closure: in the same test, derive the emitted set from the router (`build_route` over prompts that select each reviewer, or a source scan of the `evidence.append('…')` literals plus `'verification'`) and assert set equality with both module copies, plus `scripts/grok_review.py:15` choices ⊆ set. Not a blocker: today's equivalence was verified by inspection and by live-router reproduction, and `decisions.md:696-698` records the derivation rule.

### N2 — LOW — Two package numbers are still stale after the F6 correction

`requirements.md:32` claims 46 adapter tests (actual 55 in the three suites, 0.393 s) and `architecture.md:53` claims a 1703-line module with 1637 lines of tests (actual 1766 and 1890). Both are narrative evidence lines that AC-001/AC-005 receipts will cite; correct them (or drop the numbers) before the receipts step. Non-blocking, documentation truthfulness only.

### N3 — NIT — Residual truncation class from F2: dotted ids with a non-numeric suffix

The first alternative still wins partially for ids whose suffix is not digits or a single letter, because `re.match` does not require whole-token consumption: `Story 1.1-rc` yields group 2 = `1.1`, so it collides with `Story 1.1` (probed: `['story-1-1-001','story-1-1-001']`), and `compile_task_graph` then raises the duplicate-key error → `workflow-artifacts: fail`. The same fail-closed outcome as F2 but for a materially narrower input class that no observed upstream template uses. Closure would be to capture the whole id token (`[^\s:]+`) and normalize it, or to namespace colliding sections instead of truncating. Advisory-only, opt-in path, fails closed: acceptable as is.

### N4 — NIT — The closed set is only positively tested

No test asserts the rejection side (`required_evidence` with an unknown kind, a duplicate, an empty list, or more entries than kinds → the single route-level message). Behaviour was probed on this tree and is correct and fail-closed for all four shapes, so this is coverage debt only; adding it to the same test as N1 would pin both directions of the invariant.

### N5 — NIT — Receipt-kind vocabularies now differ across layers (observation, no code impact)

`schemas/change-spec.schema.json:17`, `trust-ci/src/adaptive_trust_ci/runner.py:32` and `trust-ci/holdout.example/change_spec_validate.py:27` keep the five-member spec-evidence vocabulary while the runtime set is seven.
