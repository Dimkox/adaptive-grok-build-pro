# Architecture — Workflow Artifact Adapters

The complete design is [`docs/superpowers/specs/2026-08-30-workflow-artifact-adapters-design.md`](../../../docs/superpowers/specs/2026-08-30-workflow-artifact-adapters-design.md). The anti-corruption layer is `.grok-stack/adaptive_grok/workflow_artifacts.py`; three JSON contracts live under `schemas/`; `scripts/grok_artifacts.py` is the operator interface; verification is opt-in through an active-change `workflow/manifest.json`.

Source manifest → descriptor-bound loader → closed adapter normalization → route-bound task DAG with source-status hints → native convergence comparison → ephemeral effective status from orchestration-supplied fingerprint/canonical receipts → read-only result or bounded serialized CAS publication. Exact graph/report files are derived canonical execution artifacts and persist no tree fingerprint; projections/exports are marked advisory. Per-target runtime locks serialize cooperating writers, while no-clobber creation or atomic exchange detects publication races. Any post-exchange failure rolls back before displaced content inspection; a second racing entry is retained under a bounded recovery name for forward recovery. Imported artifacts remain advisory candidates only. No API, event, database, external integration, Bitrix, or production-write path is introduced.

Canonical governance registries remain unchanged and separately authoritative. There are no active rules or accepted debt applicable to this change. Rollout is file-level opt-in and rollback removes only the manifest/projections or restores this feature branch.
