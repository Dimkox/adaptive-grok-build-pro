# Release plan — Workflow Artifact Adapters

This branch performs no deployment. Adoption is opt-in per change package by adding an explicit workflow manifest and generated graph/report. The graph stores source-status hints only; canonical receipt validation derives effective status at runtime without a tracked edit. The only canonical CAS publication targets are the active change's `workflow/task-graph.json` and `workflow/convergence-report.json`; advisory projections remain below `workflow/projections/` or `workflow/exports/`. Cooperating writers serialize on ignored, descriptor-safe locks below `.grok-stack/runtime/workflow-cas/`, and existing-file publication requires Linux `renameat2(RENAME_EXCHANGE)`. Pre/post identities include ctime, and a post-exchange mismatch rolls back before content inspection. CAS does not unlink a pathname: unique bounded `.agb-recovery-<token>` artifacts below the ignored per-change runtime directory retain staged or displaced entries after success and failure, while a failed no-clobber preservation leaves the unique `.agb-stage-<token>` entry visible beside the target. Go requires full local verification, four route-selected independent reviews, exact-PR-SHA App-owned Trust CI success, and any final production ceremony required by deployed policy. Monitor `workflow_artifacts_verifier_status` and recovery-artifact creation; any blocking or error result is no-go. Roll back by removing the opt-in manifest or restoring the feature commit before production.
