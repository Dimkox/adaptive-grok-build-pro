# Rollback plan — Workflow Artifact Adapters

Trigger on authority-boundary failure, unsafe path access, nondeterminism, source mutation, CAS identity mismatch, verifier regression, or package/installer omission. Before merge, restore the feature changes. After merge but before adoption, remove the optional `workflow/manifest.json`; verifier returns historical-compatible `skip`. The derived root `task-graph.json` and `convergence-report.json` can be regenerated from the explicit manifest and canonical sources; generated projections contain no canonical state and may be removed after their digests are recorded. Inspect `.agb-recovery-*` entries below `.grok-stack/runtime/workflow-cas/<change>/` and any fallback `.agb-stage-*` entry beside a target without following them, then reconcile each against the intended target; successful publication also retains recovery evidence. Keep every entry until an operator proves its identity and ownership, then use a separate reviewed recovery operation—CAS itself performs no automatic pathname cleanup. Ignored serialization lock files contain no workflow state and can be left in place. Native M1/M2/M3 and Trust CI require no data recovery.
