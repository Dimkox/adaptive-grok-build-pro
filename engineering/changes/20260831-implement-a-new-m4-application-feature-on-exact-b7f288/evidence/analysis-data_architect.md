# Data architecture — M4 factory control plane

**Route:** `b7f288f1e81e`
**Required product base:** `67714a1f1b87effcfabe55d5ca2770d0a68d17c1`
**Scope:** factory-only source and disposable PostgreSQL evidence; no external, production, or Trust CI database action.

## Design gate and source of truth

The current worktree is correctly on accepted M3 (`67714a1`), so it contains the M2 architecture and M3 governance interfaces required to derive frozen intake handoffs. However, `.grok-stack/runtime/active-route.json` and the new change package still bind `base_commit`/fingerprint to `1c062998`. This is a **pre-write blocker**: reroute or record an approved binding correction to `67714a1` before application changes or evidence receipts. Do not claim that a receipt for the old base validates an M4 tree based on accepted M3.

PostgreSQL `factory.*` is the sole operational source of truth for M4. It is explicitly separate from Trust CI: no factory import, connection, foreign key, view, function call, role grant, or migration may reference `trust_ci.*`, `trust_ci_schema_migrations`, or `public` Trust CI tables. Factory can retain immutable opaque identifiers/digests for an external observation, but cannot publish or authoritatively interpret a Trust CI result.

Prefer a distinct factory database. If a disposable shared cluster is used, create schema `factory` owned by `factory_migrator`, require `SET search_path TO factory, pg_catalog` for every factory role, and schema-qualify every object. Do not use `public` as a fallback search path.

## Roles and migration policy

Create only factory-specific roles:

| Role | Permissions |
| --- | --- |
| `factory_migrator` | owns `factory` schema and migrations; used only by migration command |
| `factory_runtime` | `USAGE` schema; least-privilege CRUD required by store; no DDL, no role inheritance, no access to `public`/Trust CI |
| `factory_audit_reader` | `USAGE`, `SELECT` on bounded projections/audit for local operator only; no mutation |
| `factory_test` | disposable-database owner only; never accepted outside test environment |

Revoke `CREATE` from `factory_runtime`; revoke all schema/table/sequence/function privileges from `PUBLIC`; make default privileges explicit for objects created by `factory_migrator`. The audit table grants `INSERT, SELECT` but **not** `UPDATE`, `DELETE`, or `TRUNCATE` to runtime. Role-permission integration tests must prove runtime denial of Trust CI/public access and audit update/delete.

Use immutable packaged migrations, each with SHA-256, contiguously numbered `001..N`, in `factory.schema_migrations(version primary key, name unique, sha256 char(64), applied_at timestamptz)`. `PostgresMigrator.apply()` acquires a factory-unique `pg_advisory_xact_lock`, validates all previously applied name/checksum pairs, executes each pending migration, and inserts its registry row in the **same transaction**. Missing, renamed, reordered, or altered applied migrations fail closed. Migration 001 creates the schema/ledger/intent/task/events/audit; 002 runs/attempts/fences/capacity; 003 budgets/kills/reconciliation/roles. Use expand/contract only; after accepted durable intake, recovery is global kill plus forward migration `004+`, never down migration.

## Exact logical schema and constraints

Use UUID/ULID primary keys generated by the application, `timestamptz` database time, fixed `char(40)` lowercase Git SHA and `char(64)` lowercase digest constraints, bounded `text`, and JSONB only for immutable/bounded evidence. Validate JSON byte size before insert; do not index broad JSONB bodies.

| Object | Essential columns and database enforcement |
| --- | --- |
| `intake_identities` | `(repository_id, source_type, source_id)` PK; stable serialization row used during intake/supersession |
| `accepted_intents` | `intent_digest UNIQUE`, `idempotency_key UNIQUE`, immutable `body jsonb`, frozen M1/M2/M3/policy digests, exact base SHA, `accepted_at`; no update path |
| `tasks` | `task_id PK`, accepted intent FK, repository/source identity, state, generation, current run/fence, deadline, limits, aggregate accounting/status flags, created/updated/terminal timestamps; unique active generation per intake identity; checks for allowed M4 states and `deadline <= accepted_at + interval '4 hours'` |
| `task_events` | `(task_id,event_sequence)` unique; immutable state/proposal event key unique; actor/action, bounded metadata digest/body, created time; FK task |
| `audit_log` | monotonic audit id, task/run nullable FKs using `ON DELETE RESTRICT`, previous digest/current digest, actor/action/resource/reason/correlation and bounded metadata; insert-only role permissions |
| `lease_sequences` | `task_id PK`, `last_fence bigint CHECK (last_fence >= 0)`; the sole allocator of strictly increasing task fence values |
| `runs` | `run_id PK`, task FK, owner/role, packet digest, fence, state, lease expiry, deadline, released timestamp; unique `(task_id,fence)`; fence is immutable |
| `attempts` | `(task_id, attempt_no)` unique and run FK; attempt number positive, typed failure class/code/message digest; successful claim is the only creator |
| `capacity_counters` | rows for global readers/writers and repository readers, non-negative active count with ceiling encoded in a `CHECK` or compared under lock; no dynamically invented scope keys |
| `capacity_allocations` | run/task FK, role, repository, acquired/released timestamps; unique active allocation per run; partial unique live writer index (`WHERE released_at IS NULL AND role='writer'`) |
| `budget_reservations` | task/run FK, idempotency key unique, integer `cost_usd_micros`, token/wall reservations >=0, active/released timestamps; immutable reservation reason/digest |
| `usage_observations` | unique `(run_id, provider_call_id)`, exact price-table digest/provenance, non-negative integer metering; invalid/missing price makes task accounting-blocked, not zero-cost |
| `kill_switches` | global/repository scope key, enabled/cleared times, operator actor/reason/idempotency unique, no hard delete; only an enabled current row blocks intake/claim |
| `reconciliation_runs` | immutable run id, bounded keyset cursor, started/finished/status/counts; repair events themselves carry idempotency keys so resumed scans cannot double-release |

Use `ON DELETE RESTRICT` (or no delete privilege) for durable task/run/attempt/event/audit records. Cascading deletion would contradict retention and reconciliation. Keep mutable task state as a projection only; history is reconstructed from immutable event/audit/run/attempt facts.

## Required indexes and expected plans

1. Eligible claim: partial B-tree on `(created_at, task_id)` for `state IN ('queued','retry')` with durable admission/deadline predicates selected from task columns. Claim must use `ORDER BY created_at, task_id FOR UPDATE SKIP LOCKED LIMIT 1`; not a JSONB scan.
2. Intake: unique `accepted_intents(idempotency_key)`, unique intent digest, and `intake_identities` PK. The identity row solves concurrent changed-source supersession where no existing task row exists to lock.
3. Reconciliation: partial indexes for active lease expiry `(lease_expires_at, task_id)`, unreleased allocation `(task_id, allocation_id)`, blocked/deadline task projections, and an ordered primary/keyset scan. Avoid offset pagination.
4. Capacity: live allocations by `(repository_id, role)` and partial writer singleton; counters are point lookups under row locks.
5. Operator list: `(created_at, task_id)` plus bounded repository/status predicates for opaque keyset cursor. Page maximum is 100 and statement timeout is 5 seconds.
6. Budget: task-id reservation/usage indexes with an aggregate task row locked for write; not `SUM()` over an unbounded history on every dispatch.

Before acceptance, execute `EXPLAIN (ANALYZE, BUFFERS)` in the disposable database for empty, contended, and representative queued/leased multi-repository data: claim, duplicate intake, changed-source supersession, expiry reconciliation, capacity lookup, budget reservation, and list keyset. Record plan shape/rows/buffers without connection strings. A sequential scan on a deliberately tiny test database is not itself failure, but predicate/order/index compatibility must be demonstrated.

## Transaction boundaries and lock order

All store operations use database `now()` rather than caller clock, parameterized SQL, local `lock_timeout`/`statement_timeout` of 5 seconds, and a retry only for serialization/deadlock SQLSTATEs at the command boundary with unchanged idempotency key.

1. **Intake:** lock `intake_identities` (`INSERT ... ON CONFLICT ...; SELECT ... FOR UPDATE`); lookup exact idempotency key; return exact duplicate; otherwise lock current eligible nonterminal task generations, mark them superseded, insert intent/task/event/audit atomically. Never update immutable intent body.
2. **Claim:** lock capacity counters in this strict order: global reader/writer rows, then repository rows lexicographically, then task candidate. Check global/repository kill switch in the same transaction, use `SKIP LOCKED`, verify deadline/budget/WIP, increment `lease_sequences.last_fence`, insert run/attempt/allocation, increment counters, set task projection to leased/current fence, and append event/audit. Commit as one unit.
3. **Worker mutation:** first lock task/run deterministically; require task ID, run ID, owner, fence, packet digest, expected state, unexpired lease, deadline, valid budget/accounting, and command idempotency key in the guarded SQL predicate. A zero-row update is stale fence/expired/invalid-state, never best-effort success. Heartbeat, proposal, usage, release, and terminal transition must also append the idempotent event/audit record transactionally.
4. **Release/reclaim:** lock task then global/repository counters in the same universal order; mark allocation released once, decrement counters under `CHECK >= 0`, close run/attempt, change projection, and append event/audit. A unique repair event key makes the second invocation a no-op/replay.
5. **Budget:** lock task aggregate before reservation; reject `reserved + observed + requested` above USD 25,000,000 micros / token / wall ceilings. Reconciliation locks the same task aggregate and records each trusted observation once. No valid price/metering means accounting blocked and no next reservation.

Avoid holding transactions open during API parsing, logging, subprocesses, or any future provider call. M4 has no external publication, so a transactional outbox is deliberately unnecessary; events/audit are local facts.

## Leases, fences, capacity, retry, audit, and reconciliation

- Leases are 30–300 seconds and never beyond task deadline. Reclaim issues a new run and a strictly greater fence; the old holder cannot heartbeat, commit usage/proposals, release, or complete.
- PostgreSQL establishes capacity: active readers <=20 globally, <=10 per repository, writers <=1 globally. Partial uniqueness is the writer backstop; counters and allocations must agree after every commit and reconciler repair.
- Attempt count increments only after a successful claim. Only closed typed infrastructure failures retry; initial attempt plus two retries means attempt 3 atomically becomes `dead`, releasing allocation and retaining evidence. Policy/validation/auth/security/provider-quality failures do not relabel as infrastructure.
- Kill switches stop new intake/claim per documented scope but retain live leases and evidence. Cancellation/supersession are append-only state facts, never deletion. The implementation must select and audit its live-lease policy (cooperative finish versus reclaim after expiry).
- Audit hash is `sha256(canonical(previous_digest, actor, action, resource, reason, receive_time, bounded_metadata_digest))`. Per-task chain serialization must prevent two rows choosing the same predecessor; use a task audit-head row locked with the task, or a dedicated `(task_id)` audit-chain row. Hash chaining supplements, not replaces, restrictive roles and backups.
- Reconciliation is ordered keyset work: no more than 100 candidates/call under 5 seconds. It handles expired leases, orphan allocations/counter drift, deadline and reservation exhaustion, accounting block, stale frozen handoffs, and incomplete terminal projections. Every repair is guarded by current state/fence and durable idempotency key; repeating or resuming after process loss cannot decrement capacity twice.

## Disposable PostgreSQL test plan

Only `FACTORY_TEST_DATABASE_URL` explicitly supplied for a disposable database, or a newly started factory-specific local compose Postgres 15+, may be used. Never inspect `.env` files, inherit Trust CI URLs/roles, connect to an existing operational database, or run destructive cleanup outside the named disposable target.

1. Create fresh disposable DB/schema and roles; apply migrations; assert `factory` exists and `trust_ci`/`public` access is denied to runtime.
2. Migration tests: contiguous discovery, advisory-lock concurrency, apply idempotency, renamed/missing/checksum drift rejection, role/default-privilege checks.
3. Intake tests: concurrent exact duplicate yields one task; changed source/base/frozen digest supersedes once; accepted body cannot update; event/audit append in the same committed transaction.
4. Lease tests with independent connections: competing claim yields one grant; 20 global readers/10 repo readers/one writer cap holds under contention; expiry/reclaim increases fence; delayed old-holder heartbeat/proposal/usage/release is rejected.
5. Budget/retry tests: three total infrastructure attempts end dead; no attempt increment on a failed claim; reservation aggregate cannot exceed ceiling; duplicate metering is idempotent; bad/missing pricing blocks next dispatch.
6. Recovery tests: kill blocks new claims but preserves current evidence; a two-process probe terminates a lease holder, waits only for expiry, reclaims at higher fence, rejects the late result; reconciliation is repeated and proves one allocation release/counter repair.
7. Query and boundary tests: `EXPLAIN` evidence above, statement timeout/cursor/page limit, audit `UPDATE/DELETE` denial to runtime, and no factory query names/permissions for Trust CI.

Record only PostgreSQL major version, migration names/digests, test names/counts, duration, and pass/fail. If the test started compose, stop that project afterwards; remove its named volume only via the declared disposable cleanup path. Before the first durable acceptance, dropping the exact named disposable `factory` schema is recoverable. After acceptance, use kill + backup/restore-to-separate-DB comparison + forward migration, never destructive rollback.
