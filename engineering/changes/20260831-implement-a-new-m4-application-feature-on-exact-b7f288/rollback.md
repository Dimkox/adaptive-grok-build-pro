# Rollback plan — M4 Durable Factory Task Control Plane

Trigger on any fence/capacity/budget/audit/auth/isolation invariant failure, migration drift, reconciliation imbalance, restart failure or stale evidence. Enable global kill, stop new intake/claims and the local socket process, preserve rows/audit/logs/evidence, and revert source only through a new PR.

Before first intake, only the explicitly named disposable test database/schema may be destroyed. After durable intake, never down-migrate or delete audit: restore the verified backup into a separately named comparison database or apply a reviewed forward migration `013+`. The local rollout owner records a successful logical-backup restore, exact-schema-`012` readiness check including claimable and positive-endpoint accounting consistency, effective-role denial probe, exact live-allocation/snapshot agreement, audit-chain verification and two-pass reconciliation smoke result before restart. The second reconciliation must repair zero rows; any mismatch remains no-go.

The **2026-09-08 00:00 UTC+3** deadline cannot turn a failed gate into rollout authority. If M4 is not accepted, provisional M5/M6 branches remain unmergeable and must restack after recovery; if M5 lacks a suitable rootless-isolation host, record the blocker instead of weakening isolation.
