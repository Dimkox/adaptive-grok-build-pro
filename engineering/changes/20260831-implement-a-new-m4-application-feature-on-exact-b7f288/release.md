# Release plan — M4 Durable Factory Task Control Plane

Source delivery does not activate a service. Complete local implementation, disposable PostgreSQL evidence, final verifier, five independent reviews/receipts and README parity; then a separately authorized PR must receive the App-owned exact-head Trust CI check and every signed scope before merge.

A later separately approved local rollout starts killed, verifies a backup by restoring it into a separate comparison database, and uses `adaptive-factory-admin bootstrap-local` with distinct owner/runtime DSNs to apply checksum migrations through exact schema `011`, create/validate the `NOINHERIT` runtime login membership and prove effective-role readiness. It then starts `adaptive-factory-server` only with the runtime DSN, verifies mode-`0660` UDS-only readiness, capacity/allocation and claimable/positive-endpoint accounting agreement and the three redacted metric families, and runs synthetic submit/claim/reserve/observe/release/actual-restart/two-pass-reconcile before explicitly clearing kill. Failure after durable intake requires preserved state and reviewed migration `012+`; no TCP, GitHub, external, production, provider or Trust CI mutation is part of M4.

Go requires exact accepted M3 base, real PostgreSQL evidence, role separation, late-fence rejection, bounded accounting/reconciliation, one final fingerprint and external exact-head authority. Any missing gate is no-go. Observe bounded counts for intake, queue, transitions, leases, capacity, budget, retries/dead, kills, reconciliation and auth failures without secrets, bodies, reasoning or task IDs.
