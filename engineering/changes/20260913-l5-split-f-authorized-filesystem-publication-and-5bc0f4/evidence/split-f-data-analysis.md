## Read-only paths and authorization ordering

`PublicationStore(..., readonly=True)` rejects a missing database before connecting, does not acquire/create the intent writer lock, and opens the absolute path as `path.as_uri() + '?mode=ro'`, then enables `query_only` and disables trusted schema. The URI construction preserves literal spaces, percent signs, question marks, fragments and Unicode in filenames. The frozen test `test_sqlite_uri_roundtrip_preserves_special_characters_and_readonly_does_not_create` exercises this exact store path and an actual temporary reopen. Do not replace `as_uri` with URI string concatenation or `immutable=1`: readers must see SQLite's durable WAL state.

Factory `_bundle` separately checks tenant/repository scope before accessing landing state; it validates database file ownership/mode/link count, opens landing SQLite with `as_uri()` and `mode=ro`, validates application/version, then selects the exact tenant/repository/job. The retained artifact and source bindings, canonical origin, output-root disjointness, immutable artifact digests and archive validation are checked before a publication bundle is returned. This does not instantiate `SQLiteLandingJobStore`, perform its startup recovery, acquire model credentials or replay a provider. The SQL row and retained files are separate reads; integrity checks, rather than a cross-filesystem transaction claim, protect the assembled bundle.

Be precise about the authority contract. `main` checks `--live` and that authority is callable **before config or publication-state access**. It does not validate the actual grant before every state read: apply must load the persisted request to identify the exact resource. It then observes the target and validates the artifact before calling authority. A valid returned digest is required before `prepared -> inflight` and before any filesystem effect. A failed grant leaves the prepared intent and publication target unchanged in the frozen regression. Opening a writable store can create local state first, while `already_observed` and baseline-drift outcomes can update local bookkeeping without invoking authority. These are not unauthorized deployment effects and should not be described as a stronger blanket promise of zero local state access or mutation without a grant.

The wrapper verifies the exact repository remote forms, active route/change, well-formed current HEAD/fingerprint, one exact external-write action/resource, one matching delegated grant, allowed consent source and a bounded aware expiry interval. It stores only the matching grant's digest in the intent. Tests use synthetic grant bytes and mock identity functions; they neither issue an actual grant nor create external merge authority.

## Effect, ambiguity and recovery behavior

The sequence is: observe exact baseline, validate bundle, validate authority, durably commit `inflight` with grant digest, perform the filesystem operation, then reconcile from fresh observation. A crash after intent commitment cannot cause automatic replay: subsequent apply routes `inflight` to reconciliation. Non-prepared terminal phases simply return their stored result. A normal adapter exception after intent also routes to observation; an interruption outside `Exception` leaves `inflight` available for later observation.

Stage uses exclusive release-directory creation, immutable final file/directory modes, content/manifest checks and fsync. It preserves partial attempts instead of overwriting or resuming them. Activate checks the baseline under the target lock and atomically replaces `current` with an exact validated relative release pointer, followed by directory fsync. Restore is an independently prepared and authorized request tied to a previously activated intent, its exact prior baseline and the currently observed release. Restoring the empty prior baseline removes the current pointer; it is not a broad rollback command.

Reconcile makes no filesystem effect call. It can write publication SQLite: observed success becomes staged/activated/restored; unavailable observation becomes `needs_human/observation_unavailable_no_replay`; an unconfirmed effect becomes `needs_human/effect_ambiguous_no_replay`. The frozen pointer-failure test covers ambiguous activation and forbids replay on the next reconciliation call. It does not, by itself, prove process-restart recovery after a committed effect or the complete restore chain. New real effects after ambiguity require a separately prepared exact request and authority; do not manually reset phases to manufacture replay eligibility.

## Concrete validation gap and bounded test additions

It does not verify declared types, NOT NULL flags, primary-key/unique constraints, STRICT mode, or unexpected views/triggers.
